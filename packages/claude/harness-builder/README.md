# harness-builder

**Claude Code에게 "하네스 만들어줘" 한마디로, 반복 업무의 실행 절차를 함께 설계하고 스킬로 만들어주는 메타 팩토리입니다.**

여행 계획, 채용 서류 검토, 분기 마케팅 기획, 엑셀 정산 자동화, 전략 옵션 비교 — 도메인이 무엇이든, Claude가 인터뷰로 요구사항을 끌어내고 **역할 분해 → 산출물 계약 → 승인 게이트**를 갖춘 재사용 가능한 절차(하네스)를 여러분의 프로젝트에 생성합니다.

## 하네스(harness)란?

한 번 잘 설계해두고 반복해서 돌리는 **구조화된 실행 절차**입니다. 프롬프트 한 줄과 다른 점:

- **역할이 나뉘어 있습니다** — 예: 리서치 → 초안 → 관점 검증 → 종합. 각 역할은 실제 서브에이전트로 동작합니다.
- **산출물이 계약되어 있습니다** — 역할 사이에 무엇이 어떤 형식으로 오가는지 미리 정의됩니다.
- **승인 게이트가 있습니다** — 파일 수정, 메일 발송, 예약·결제처럼 되돌리기 어려운 일은 반드시 여러분의 승인을 받고 실행합니다.

만들어진 하네스는 `/이름` 으로 언제든 다시 호출할 수 있는 Claude Code 스킬이 됩니다.

## 설치

프로젝트 루트에서:

```bash
npx @hb-kit/cli claude-harness-builder
```

`.claude/skills/harness-builder/` 에 스킬이 설치됩니다. [Claude Code](https://claude.com/claude-code)가 필요하며, 별도 의존성은 없습니다.

## 사용법

Claude Code에서 이렇게 요청하세요:

```
/harness-builder
```

또는 자연어로:

```
여행 계획 하네스 만들어줘
채용 서류검토 하네스 만들어줘
엑셀 정산 자동화 하네스 만들고 진행해줘
```

### 이후 흐름

1. **인터뷰** — Claude가 목적·역할 구성·도구·발동 조건을 짧은 질문 몇 개씩 나눠 묻습니다. 한 문장짜리 아이디어만 있어도 충분합니다.
2. **청사진 승인** — 설계안(역할·산출물·게이트·생성될 파일)을 표로 보여주고 확인을 받습니다.
3. **생성** — 승인한 파일 목록대로만 만듭니다. 하네스 본체(`SKILL.md`)와 역할별 에이전트 파일이 생깁니다.
4. **바로 실행 (선택)** — "만들고 진행해줘"라고 했다면, 방금 만든 하네스로 그 자리에서 첫 실행까지 이어갑니다.

### 예시: 이렇게 만들어집니다

"채용 서류검토 하네스 만들어줘" → 인터뷰 후:

```
.claude/skills/resume-review/SKILL.md      ← 절차 본체 (/resume-review 로 호출)
.claude/agents/resume-review/screener.md   ← 서류 심사 에이전트
.claude/agents/resume-review/verifier.md   ← 교차 검증 에이전트
```

다음부터는 `/resume-review` 한 번으로 같은 절차가 반복됩니다.

## 특징

- **도메인 불문** — 개인 생활부터 인사·영업·마케팅·데이터 분석·코드 작업까지 같은 골격으로 만듭니다. 도구가 하나도 없어도 됩니다(조언·전략 비교 같은 순수 추론 하네스).
- **진짜 오케스트레이션** — 역할을 흉내 내는 게 아니라 실제 서브에이전트 파일로 만들고, 병렬 팬아웃·검증 루프가 필요하면 Workflow 스크립트로 제어 흐름을 고정합니다.
- **승인 없이는 아무것도 하지 않습니다** — 설계 승인과 파일 생성 승인이 분리되어 있고, 만들어진 하네스에도 부수효과(파일 수정·외부 전송·예약·결제) 앞 승인 게이트가 반드시 들어갑니다.
- **민감정보 보호** — 인사·매출·개인정보를 다루는 하네스에는 "외부 전송·공유 전 승인" 게이트가 자동으로 강제됩니다.
- **품질 루프 내장** — 필요에 따라 관점 패널, 적대 검증, 체크리스트 검수, Best-of-N 같은 검증 패턴을 하네스에 넣을 수 있습니다.
- **자기 고도화 루프 내장** — 만들어진 하네스는 실행을 거듭하며 마찰을 회고(매 실행 경량 회고 + 누적 임계 강제 회고)하고, 승인 게이트(G-개선)를 거쳐 자기 절차를 스스로 개선합니다. 플랫폼 일반 결함이면 빌더로 환류해 다음 하네스까지 함께 나아집니다.
- **이식 가능** — 스킬 폴더 하나로 자급자족합니다. 다른 프로젝트의 `.claude/skills/` 로 복사하면 그대로 동작합니다.

## FAQ

**Q. 일회성 작업에도 쓰나요?**
아니요. 반복 가치가 없는 요청은 하네스로 만들지 않고 그냥 처리하도록 안내합니다.

**Q. 만든 하네스를 수정하고 싶으면?**
`/harness-builder` 를 다시 호출해 해당 하네스의 업데이트를 요청하면 됩니다.

**Q. 팀원과 공유하려면?**
생성물은 전부 프로젝트 안 파일(`.claude/skills/`, `.claude/agents/`)이므로 git에 커밋하면 팀 전체가 같은 하네스를 씁니다.
