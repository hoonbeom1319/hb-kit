## [실행 구성] — ⓐ/ⓑ/ⓒ 중 택1 (나머지 구획 삭제)

### ⓐ 순차 인라인 — 역할이 적고 컨텍스트 공유가 유리할 때

- 메인 대화가 역할 1 → 2 → … 순으로 직접 수행한다. 에이전트 파일 없음.
- 역할 전환 시 이전 역할의 아티팩트를 명시적으로 닫고 다음 역할을 선언한다 (경계 뭉개짐 방지).

### ⓑ 서브에이전트 병렬 스폰 — 역할이 독립 컨텍스트를 가질 가치가 있을 때

**에이전트 팀** — 각 역할을 실제 서브에이전트 파일로 물질화한다:

| 역할    | 에이전트 파일                          | 병렬 가능?          |
| ------- | -------------------------------------- | ------------------- |
| {역할1} | `.claude/agents/{하네스}/{역할1}.md`   | {예: 역할2와 병렬}  |
| …       | …                                      | …                   |

- 독립 가능한 역할은 Agent 툴로 **병렬 스폰** → 각자 아티팩트 산출 → 부모가 **종합** → 의존 역할은 순차.
- 예: `[역할1 ∥ 역할2] → 종합 → 역할3`
- 스폰 시 에이전트 지정은 네임스페이스된 `name`(`{하네스}-{역할}`)으로 한다 — 파일 경로가 아니라 `name`이 식별자다.

### ⓒ Workflow 오케스트레이션 — 팬아웃·루프·적대검증이 절차의 본체일 때

에이전트 팀은 ⓑ와 동일하게 물질화하고, 제어 흐름을 아래 스크립트로 고정한다.
실행: Workflow 툴에 이 스크립트를 인라인 전달 (별도 파일 아님 — 이 SKILL.md가 단일 진실 공급원).

```js
export const meta = {
  name: '{하네스-이름}',
  description: '{한 줄}',
  phases: [{ title: '{단계1}' }, { title: '{단계2}' }],
}
phase('{단계1}')
// 예: 항목별 팬아웃 → 각 결과를 즉시 검증 (barrier 없이 pipeline)
const results = await pipeline(
  {대상목록},
  item => agent(`{역할 프롬프트}: ${item}`, { agentType: '{하네스-이름}-{역할1}', phase: '{단계1}', schema: {스키마} }),
  r => agent(`검증: ${JSON.stringify(r)}`, { agentType: '{하네스-이름}-{검증역할}', phase: '{단계2}', schema: {스키마} }),
)
return results.filter(Boolean)
```

- ⛔ 부수효과 게이트는 **스크립트 밖**(메인 대화)에서 통과시킨다 — Workflow 안에서 사용자 승인 없이 부수효과를 실행하지 않는다.
