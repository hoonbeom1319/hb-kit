# 도메인 툴킷 (Domain Toolkits)

> harness-builder 인터뷰 파도 ④(도구 조각 선정)에서 이 표와 대조한다.
> **철칙**: 현재 환경에서 확인 안 된 도구를 ✅로 적지 않는다. "이식 시 확인" 열이 확인 방법이다.
> 도구가 하나도 안 잡혀도 하네스는 성립한다 — 마지막 "순수 추론" 행 참조.

## 1) 목적별 도구 매핑

| 목적                | 도구 조각                                                                 | 이식 시 확인                                                | 비고                                                                 |
| ------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------- |
| **정보 수집·리서치** | WebSearch / WebFetch, `deep-research` 스킬(있으면)                        | 스킬 목록·툴 목록에 존재하는지                               | 시장·경쟁사 조사, 여행지·시세 조사, 정책·법규 확인                    |
| **웹 조작**         | 브라우저 자동화 MCP (예: claude-in-chrome)                                | MCP 연결 여부 + 사이트 권한                                  | 사내 웹 시스템 조회·입력, 폼 작성. **입력(쓰기)은 부수효과 게이트 뒤** |
| **파일·데이터 처리** | Read/Write/Edit + Bash·PowerShell 스크립트 (엑셀: python `openpyxl`·`pandas`, CSV 직접 처리) | `python --version` 등 런타임 확인                | 엑셀 자동화, 정산·집계, 대량 파일 정리. **덮어쓰기는 게이트 뒤**       |
| **문서·보고 산출**   | Write(마크다운 리포트), 사내 위키 MCP(예: Confluence — 있으면)            | MCP 연결 여부                                                | 기획서·검토 리포트·회의록. **위키 게시는 외부 공유 게이트 뒤**         |
| **디자인·화면 참조** | 디자인 툴 MCP(예: Figma — 있으면)                                         | MCP 연결 여부                                                | 화면 검수·디자인 스펙 대조                                            |
| **일정·반복 실행**   | schedule/Cron 계열 기능, `/loop`                                          | 해당 기능 가용 여부                                          | 주간 리포트, 정기 점검 하네스                                         |
| **사람에게 묻기**    | AskUserQuestion (인터뷰·승인·선호 확인)                                   | 항상 가용                                                    | 게이트 통과, 취향·조건 수집 (여행 예산, 채용 기준 등)                 |
| **역할 오케스트레이션** | Agent(서브에이전트 병렬), Workflow(팬아웃·루프·적대검증)               | 항상 가용 (Claude Code)                                      | 실행 형태 ⓑ/ⓒ의 기반                                                 |
| **코드 작업**       | 프로젝트의 코드 규칙·전용 스킬을 우선 따른다                              | 대상 프로젝트의 CLAUDE.md·규칙 확인                          | 코드 전용 팩토리가 따로 있으면 그쪽에 양보                            |
| **순수 추론 (도구 0개)** | 역할·관점 분해만으로 수행                                             | —                                                            | 육아 조언, 전략 옵션 비교, 의사결정 프레임 — 품질 루프가 사실상 도구   |

## 2) 품질 루프 패턴

검증이 필요한 하네스는 아래 중 하나 이상을 [품질 루프] 구획에 채택한다.

| 패턴              | 방식                                                                                     | 어울리는 곳                                     |
| ----------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------ |
| **관점 패널**     | 산출물을 서로 다른 관점 역할(예: 재무·리스크·고객)이 각자 비판 → 부모가 종합             | 전략·기획·계획서 (정답 없는 판단형)              |
| **적대 검증**     | 검증 역할이 findings/주장을 **반박하려고 시도** → 반박 못 버틴 것만 통과                 | 검수·감사·리서치 결과 (거짓 양성 제거)           |
| **체크리스트 검수** | 도메인 체크리스트(하네스에 내장)와 대조해 누락 항목 열거                                | 문서·기획서·정산 (완전성 검증)                   |
| **Best-of-N**     | 같은 과제를 N회 독립 산출 → 심사 역할이 채점·선별, 차점의 좋은 부분 접목                 | 창작·네이밍·카피 (탐색 폭이 가치)                |

- 공통 상한 규칙: 검증→수정 루프는 **최대 2회** 등 상한을 하네스에 명시하고, 초과분은 멈추고 사용자에게 핸드백한다.

## 3) 민감정보 취급 (인터뷰 파도 ①에서 확인)

- 인사(급여·평가·개인정보), 매출·재무, 고객 데이터를 다루는 하네스는:
  - **"외부 전송·공유 전 승인" 게이트 필수** (메일·메신저·위키 게시·외부 업로드 전부)
  - 산출물 저장 위치를 인터뷰에서 확정한다 (공유 폴더에 무심코 남기지 않도록)
  - 외부 웹서치 쿼리에 내부 실데이터(이름·수치)를 넣지 않는다 — 일반화한 질문으로 우회

## 4) 이식 체크 절차 (새 프로젝트에서 첫 사용 전)

1. 스킬 목록·MCP 연결 상태를 확인해 위 표의 "이식 시 확인"을 훑는다.
2. 산출 하네스의 [도구 조각] 표에서 가용 상태를 현재 환경 기준으로 갱신한다 (✅→🚧 강등 포함).
3. 🚧가 된 조각은 "미완 시 대안" 열대로 우회하거나, 대안이 없으면 하네스 In/Out을 좁힌다.
