# harness-builder (범용 메타 팩토리)

> 산출물 골격: `templates/harness.template.md` · 역할 골격: `templates/agent.template.md`
> 도메인별 도구 매핑: `references/domain-toolkits.md`
>
> **자급자족 원칙**: 이 폴더는 어느 프로젝트로든 통째로 복사해 바로 쓸 수 있다.
> 이 폴더 밖의 파일을 참조하지 않는다 (산출 하네스 파일 생성은 예외).

## 목적

- 호출하면 **인터뷰로 함께 설계**해 임의 도메인의 하네스를 **계약 우선**(역할·아티팩트·게이트)으로 생성한다.
- 도메인을 가리지 않는다 — 여행 계획·육아 조언 같은 개인 주제부터 채용 프로세스·분기 마케팅 기획·전략 옵션 비교·엑셀 리포트 자동화·코드 작업까지 같은 골격으로 빚는다.
- 도구가 없는 도메인도 성립한다 — 역할·관점 분해 자체가 가치인 **순수 추론 하네스**(조언·전략·기획)를 지원한다.
- **Claude Code 전용 — 진짜 오케스트레이션을 쓴다.** 역할은 실제 서브에이전트 파일로 물질화하고,
  팬아웃·루프·적대검증이 필요한 하네스는 Workflow 스크립트로 결정론적 제어 흐름을 내장한다. 가짜 병렬 서술 금지.

## 트리거

1. **`/harness-builder`** 직접 호출
2. **"{X} 하네스 만들어줘"** / **"{X} 하네스 만들고 진행해줘"** 등 새 하네스 구축 의도가 명시된 요청
   (예: "여행 계획 하네스 만들어줘", "채용 서류검토 하네스 만들어줘", "분기 마케팅 기획 하네스 만들고 진행해줘", "엑셀 정산 자동화 하네스 만들어줘")

> **우선순위**: 현재 프로젝트에 특정 도메인 전용 팩토리가 따로 있으면(예: 코드 전용 하네스 팩토리),
> 그 도메인 요청은 전용 팩토리에 양보한다. harness-builder는 나머지 전부를 받는다.

## 적용 / 제외 범위

- **In (적용)**: 임의 도메인 신규 하네스의 인터뷰 기반 설계·생성, 이 팩토리가 만든 하네스의 업데이트, 생성 직후 1회 핸드오프 실행(H0)
- **Out (제외)**: 이미 존재하는 하네스 절차의 반복 실행(각 하네스가 담당 — H0는 생성 직후 1회만), 하네스 없이 그냥 처리하면 되는 일회성 요청의 스킬화 강요

## 입력

- 만들 하네스의 주제·의도 (한 문장이면 충분 — 나머지는 인터뷰로 채운다)

## 절차

### 1) 인터뷰 — 5개 파도 ⛔ 한꺼번에 다 묻지 않는다

파도당 2~3개 질문을 던지고, 답을 받아 이해를 맞춘 뒤 다음 파도로 넘어간다.
호출자가 이미 답한 차원은 건너뛴다. 모호하면 추천안을 제시하고 확인받는다.

| 파도  | 차원                        | 끌어낼 것                                                                                                                                         |
| ----- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **①** | 도메인·목적·반복성 + 맥락   | 무엇을 구조화·자동화? 어떤 도메인? 반복 주기? **이해관계자·보고 대상은? 민감정보(인사·매출·개인정보)를 다루나?**                                    |
| **②** | 역할 분해 + 아티팩트 계약 + 실행 형태 | 몇 개 역할로? (예: 리서치 → 초안 → 관점검증 → 종합) 역할 사이 산출물은 무엇이고 어떤 형식·위치인가? **실행 형태는?** — ⓐ 순차 인라인 ⓑ 서브에이전트 병렬 스폰 ⓒ Workflow 오케스트레이션(팬아웃·루프·적대검증이 절차의 본체일 때) |
| **③** | 트리거/In·Out + 부수효과    | 언제 발동? 무엇은 제외? **이 하네스가 세상에 미치는 부수효과를 전부 열거** (아래 "부수효과 게이트" 표 참조)                                        |
| **④** | 도구 조각 + 품질 루프       | `references/domain-toolkits.md`와 대조해 쓸 도구 선정 + 가용 상태(✅/🚧). 품질 루프 필요 여부·형태(관점 패널/적대 검증/체크리스트/없음)             |
| **⑤** | 즉시 실행 여부              | 생성 직후 지금 요청으로 **1회 실행(H0)까지 원하는가?** 원하면 실행 입력(예: 여행지·기간, 검토할 엑셀 파일)을 이 시점에 확보                        |

- 파도 ①에서 **민감정보가 확인되면**, 산출 하네스의 부수효과 게이트에 "외부 전송·공유 전 승인"을 **강제 배치**한다 (선택 아님).

### 2) G1 — 청사진 제시 ⛔ 승인 없으면 진행 금지

`templates/harness.template.md` 골격에 맞춰 청사진을 표로 제시한다:

> **목표 / 도메인·이해관계자 / 트리거 / In·Out / 역할 분해 / 아티팩트 계약 / 부수효과와 게이트 위치 / 도구 조각(가용 상태) / 품질 루프 / 생성될 파일 목록 / H0 실행 여부**

- 모든 산출 하네스는 **부수효과 게이트를 1개 이상** 포함해야 한다. 부수효과가 전혀 없는 순수 추론 하네스만 예외이며, 예외라는 사실을 청사진에 명시한다.
- 승인은 명시적 긍정만 인정. **G1 승인 ≠ G2 승인** — "청사진 좋네"는 파일 생성 승인이 아니다.

### 3) G2 — 파일 경로 전체 목록 제시 ⛔ 승인 없으면 파일 작업 일절 금지

**산출물 세트 — 하네스 1개 = 다음 파일들:**

| #   | 파일                                       | 역할                                                                                     |
| --- | ------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 1   | `.claude/skills/{이름}/SKILL.md`           | **본체** — 계약 우선(역할·아티팩트·게이트·도구) + 실행 구성 (ⓒ면 Workflow 스크립트를 이 안에 인라인 내장) |
| 2   | `.claude/agents/{이름}/{역할}.md` (역할 수만큼) | **에이전트 팀** — 독립 컨텍스트 가치가 있는 역할만 물질화 (역할 1개짜리 하네스는 생략) |

- ❌ "하네스를 만들겠습니다" → ✅ "`.claude/skills/xxx/SKILL.md` 신규 + `.claude/agents/xxx/{역할}.md` N개 — 진행할까요?"
- 승인받은 목록 외 파일이 필요해지면 **다시 G2**.

### 4) 생성

- 본체 SKILL.md는 `templates/harness.template.md`의 모든 섹션을 채운다 (해당 없는 선택 구획은 통째로 삭제).
- 역할별 에이전트는 `templates/agent.template.md`로 생성 — 본문은 계약의 역할 행 + 아티팩트 계약에서 파생한다.
- **에이전트 `name`은 `{하네스}-{역할}`로 네임스페이스한다.** 에이전트는 파일 경로가 아니라 frontmatter `name`으로 전역 해석되므로,
  네임스페이스 없이는 하네스끼리 역할 이름(예: "리서처")이 충돌한다. 파일은 `.claude/agents/{하네스}/` 밑에 두되 `name`이 곧 식별자다.
- **실행 형태 ⓒ(Workflow)를 택했으면** 본체의 [실행 구성]에 실제 실행 가능한 Workflow 스크립트를 인라인으로 내장한다
  (`export const meta` + `agent()/pipeline()/parallel()` — 별도 파일 아님, 이식성 유지). 스크립트의 각 `agent()` 호출은
  `agentType`으로 네임스페이스된 에이전트 `name`(`{하네스}-{역할}`)을 지정한다.
- **도구 조각은 가용 상태(✅/🚧)를 정직하게 표기**한다. 준비 안 된 도구를 ✅로 적지 않는다. 미완 의존성이 있으면 템플릿의 "의존성 성숙도" 구획을 채운다.
- 완료 후 커밋을 제안한다 (git 프로젝트인 경우). 커밋도 사용자 승인 후에만.

### 5) H0 — 핸드오프 런 (인터뷰 ⑤에서 요청된 경우만)

- 생성 완료 직후, **방금 만든 하네스의 절차를 그대로 따라** 원 요청을 1회 실행한다.
- 산출 하네스에 정의된 부수효과 게이트를 **생성자라고 건너뛰지 않는다** — 첫 실행이 곧 게이트 검증이다.
- 실행 중 절차의 결함이 드러나면: 실행을 마친 뒤 발견된 결함을 보고하고, 본체 SKILL.md 수정을 **별도 승인**으로 제안한다 (실행 중 무단 수정 금지).

## 부수효과 게이트 (도메인 중립 정의)

"코드 수정 전 승인"의 일반화. 산출 하네스는 아래 유형 중 자기에게 해당하는 **모든 부수효과 앞에** 승인 지점을 둔다. 게이트 전에는 읽기 전용 탐색·초안 작성만 허용된다.

| 부수효과 유형        | 예                                                             |
| -------------------- | -------------------------------------------------------------- |
| 파일 생성·수정·삭제  | 코드 수정, 엑셀 덮어쓰기, 문서 대량 생성                        |
| 외부 전송·공유       | 메일·메신저 발송, 사내 위키 게시, 외부 서비스 업로드            |
| 예약·구매·결제       | 항공권·숙소 예약, 유료 API 호출, 구독 결제                      |
| 시스템 기록          | 사내 시스템에 티켓·이슈·결재 생성, DB 쓰기                      |
| 대량·비가역 작업     | 일괄 변경, 삭제, 발송 — 되돌리기 어려운 모든 것                 |

- **민감정보(인사·매출·개인정보)를 다루는 하네스는 "외부 전송·공유 전 승인" 게이트가 필수다.**

## 산출물

- 하네스 1개당: 본체 SKILL.md + 에이전트 파일(역할 수, 해당 시)
- H0 실행 시: 그 하네스가 정의한 산출물 (여행 계획서, 검토 리포트, 자동화 결과물 등)

## 이식 (다른 프로젝트로 가져가기)

1. 이 폴더(`.claude/skills/harness-builder/`)를 대상 프로젝트의 `.claude/skills/`로 **통째로 복사**한다. 끝.
2. 첫 사용 전 `references/domain-toolkits.md`의 "이식 시 확인" 열을 따라 대상 환경의 도구 가용성을 재확인한다 (MCP·CLI는 프로젝트마다 다르다).
3. 이 팩토리가 만든 하네스도 옮기려면 `.claude/skills/{이름}/` + `.claude/agents/{이름}/`을 함께 복사한다.

## 하지 말 것

- 인터뷰 없이(또는 5파도 미확인 상태로) 바로 청사진·파일 생성
- 게이트 건너뛰기·묶기 (G1 ≠ G2, H0라고 산출 하네스의 게이트 생략 금지)
- 부수효과 게이트 없는 하네스 산출 (순수 추론 예외는 청사진에 명시된 경우만)
- 민감정보 하네스에 "외부 전송·공유 전 승인" 게이트 누락
- 에이전트 `name`을 네임스페이스 없이 짓는 것 (하네스 간 이름 충돌)
- 준비 안 된 도구를 ✅로 표기하는 것
- 이 폴더 밖 파일 참조를 본체·산출물에 박는 것 (이식성 파괴 — 산출 하네스 파일 생성은 예외)
- 일회성 요청을 억지로 스킬화하는 것 (반복 가치가 없으면 그냥 처리하라고 안내)
